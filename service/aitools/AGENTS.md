## T/ 与 V/ 提示词模板机制（两条消费路径不同，容易踩坑）

| 目录 | 使用节点 | 合成方式 |
|---|---|---|
| `T/` | `MultiFunAINode`（`PromptManager("T")`） | **字符串拼接**：`system_prompt + 模板正文 + 用户prompt`，**不做 format** |
| `V/` | `Qwen3VlImage`（`PROMPT_FILE_DIR = "V"`） | `build_final_prompt()`：仅当文件名以 `@` 开头才 `模板.format(用户输入)`，`{}` 被替换；否则 custom_prompt 非空时模板被忽略、为空时模板原样发出 |

- 因此 `V/` 里的文件普遍带 `@` 前缀（如 `@H3多参考生视频.txt`），而 `T/` 下没有 `@` 文件 —— 这是刻意区分，不是遗漏。
- `T/` 模板末尾写 `# 用户内容描述如下` + 单独一行 `{}` 只是**字面分隔标记**（用户文本会被拼在它后面），保留这个写法与既有多数模板一致。
- 通用约定：除末尾那一个 `{}` 外**不要出现其它花括号**，否则将来若被 `@`/format 路径消费会出错。
  - 实测：`@` 模板的 `花括号转义->format` 回滚（`replace('{','{{').replace('}','}}').replace('{{}}','{}')`）会把 JSON 示例 `{"a": 1}` 原样还原，
    但**只能有一个 `{}`**（每个 `{}` 都是一个位置参数，两个就 IndexError）；`{0}` 会被转义成字面量、不是占位符。
  - `@` 模板**正文里不能出现 `@` 字符**：用户描述为空时模板原样发出，而 `replace("@", "image"/"video")` 会把正文里的 `@` 换成 image/video（会污染内容）。
  - `T/` 模板末尾的 `{}` 是**字面标记**（MultiFunAINode 不做 format，`{}` 会原样进入提示词）；新写模板可以直接以
    `用户需求描述如下：` 结尾而不写 `{}`（更干净），两种都能用；既有模板不必改。
- **`MultiFunAINode` 会先清洗模板正文**：`clean_prompt_keywords()` 的 `思考|分析|推理|步骤|```[\s\S]*?``` ` 会在
  拼进提示词之前被替换掉 → 写 `T/` 模板时**绝不能出现这四个词和三反引号围栏**（否则句子被静默挖空）。
  `V/` 路径不清洗模板，但输出会过 `clean_think_content()`（会删掉输出里的 ``` 与字面 `think`）。
- `PromptManager("T")` / `PromptManager("V")` 传的是**相对路径**，已在 `PromptManager.__init__` 里按 `__file__` 所在目录转成绝对路径 —— 否则会按启动 CWD（`D:\AI\ComfyUI-Dev`）去找目录，启动日志必现 `[警告] prompt目录不存在或非法：T` / `：V`，两个下拉退化成 `请放入提示词文件`（踩过一次，别把这段解析删掉）。
- 模板在 `PromptManager.__init__` 时（模块导入时）一次性加载，`refresh()` 无人调用 → **新增/修改 txt 后必须重启 ComfyUI 或点"重载插件"**；下拉项的值就是文件名。加载完成只打一行汇总（`[成功] 加载prompt文件：T 共 40 个`），**不要恢复逐个文件打印**（启动日志会被 87 行刷屏）。

## Qwen-Image-2.1 提示词模板（已移植官方 skill 三份）

来源：`D:\AI\ComfyUI-Dev\qwen-image-2.1-skill\skills\qwen-image-2-1-prompter`（SKILL.md + `references/t2i_rules.md` +
`references/edit_rules.md` + `references/cheat_sheet.md`）：正是官方那套「8 步文生图框架 / 编辑属性解耦 / 词汇与比例速查表」。

| 文件 | 用途 | 输出 |
| ---- | ---- | ---- |
| `T/qwen2.1-文生图-技能完整版.txt` | 文生图（单段英文描述 + 比例），含词汇速查表 | 一行 JSON `{rewritten_prompt, wh_ratio}` |
| `V/@qwen2.1-图生图-技能完整版.txt` | 单图重绘/风格化：保主体、保构图、只改被点名属性 | `{rewritten_prompt, wh_ratio, ratio_follow}` |
| `V/@qwen2.1-改图-技能完整版.txt` | 局部修改 / 多图合成 / 扩图：含 `<image1>` 标签强制、画布选择表、wh_ratio 与 ratio_follow 互斥 | 同上 |

- 三份都在正文里写死了四条硬规则（易被改坏，改时先看）：文生图正文**永远英文**；编辑模式正文语言随用户指令
  （中文指令→中文），引号内渲染文字另按「用户指定 > 原图主导语言 > 用户指令语言」且**单语种**；文生图正文里
  **不许出现比例/像素**；两个尺寸字段**互斥**（一个空另一个才有值）。
- 输出都是**一行 JSON**（不给围栏）→ 下游可接 `JSON转提示词` 之类节点拆 `rewritten_prompt`/`wh_ratio`。
- 体积：T 约 12KB / 3.7k token，两份 V 各约 6.5-7.3KB / 1.3-1.5k token（`n_ctx=8192` 富余）。

## YuE2 音乐模板（T/ 下两份）

| 文件 | 用途 |
| ---- | ---- |
| `YuE2音乐提示词生成-简约版.txt` | 55 行极简规则，快速使用 |
| `YuE2音乐提示词生成-丰富版.txt` | 269 行：曲风/乐器/人声/情绪词库 + 段落标签表 + 时长→行数对照表 + 5 个不同风格示例（电子/古风/摇滚/Lo-fi/说唱） |

- 输出两段：`[style]` 英文标签行 + `[lyrics]` 段落歌词，直接对应 YuE2 节点的两个输入框。
- 硬约束来自 YuE2 请求字段：**没有 bpm / reference_audio / phoneme / 参考歌手字段** → 速度只能写进 `style`，禁止写翻唱/模仿歌手。
- `lyrics` 只放段落标签（`[Verse]`/`[Chorus]`/`[Bridge]`/`[Outro]` 等）+ 歌词正文；歌词长度直接决定歌曲时长，过长会触发 `truncated` 截断。
- `cot` 模式由节点决定，不要写进提示词。
- **时长→行数换算（实测得出）**：1 个语义 token = 40ms；**每行歌词秒数 ≈ 330 ÷ BPM**（→ 需要行数 ≈ 目标秒数 × BPM ÷ 330；说唱/密集短句 ÷1.5）。16 行@88 BPM 实测 54.9/61.0/61.9 秒（±6% 波动）；语义硬上限 9000 帧 = 360 秒。丰富版模板 3.2 节就是这套公式 + 速查表，且其 5 个示例的标注行数与实际行数已用脚本校验一致（教行数预算的模板必须自洽）。
