# aitools（AI 推理节点）

## T/ 与 V/ 提示词模板机制（两条消费路径不同，容易踩坑）

| 目录 | 使用节点 | 合成方式 |
|---|---|---|
| `T/` | `MultiFunAINode`（`PromptManager("T")`） | **字符串拼接**：`system_prompt + 模板正文 + 用户prompt`，**不做 format** |
| `V/` | `Qwen3VlImage`（`PROMPT_FILE_DIR = "V"`） | `build_final_prompt()`：仅当文件名以 `@` 开头才 `模板.format(用户输入)`，`{}` 被替换；否则 custom_prompt 非空时模板被忽略、为空时模板原样发出 |

- 因此 `V/` 里的文件普遍带 `@` 前缀（如 `@H3多参考生视频.txt`），而 `T/` 下没有 `@` 文件 —— 这是刻意区分，不是遗漏。
- `T/` 模板末尾写 `# 用户内容描述如下` + 单独一行 `{}` 只是**字面分隔标记**（用户文本会被拼在它后面），保留这个写法与既有多数模板一致。
- 通用约定：除末尾那一个 `{}` 外**不要出现其它花括号**，否则将来若被 `@`/format 路径消费会出错。
- 模板在 `PromptManager.__init__` 时（模块导入时）一次性加载，`refresh()` 无人调用 → **新增/修改 txt 后必须重启 ComfyUI 或点"重载插件"**；下拉项的值就是文件名。

## YuE2 音乐模板（T/ 下两份）

| 文件 | 用途 |
| ---- | ---- |
| `YuE2音乐提示词生成-简约版.txt` | 55 行极简规则，快速使用 |
| `YuE2音乐提示词生成-丰富版.txt` | 269 行：曲风/乐器/人声/情绪词库 + 段落标签表 + 时长→行数对照表 + 5 个不同风格示例（电子/古风/摇滚/Lo-fi/说唱） |

- 输出两段：`[style]` 英文标签行 + `[lyrics]` 段落歌词，直接对应 YuE2 节点的两个输入框。
- 硬约束来自 YuE2 请求字段：**没有 bpm / reference_audio / phoneme / 参考歌手字段** → 速度只能写进 `style`，禁止写翻唱/模仿歌手。
- `lyrics` 只放段落标签（`[Verse]`/`[Chorus]`/`[Bridge]`/`[Outro]` 等）+ 歌词正文；歌词长度直接决定歌曲时长，过长会触发 `truncated` 截断。
- `cot` 模式由节点决定，不要写进提示词。
- **时长→行数换算（实测得出）**：1 个语义 token = 40ms；**每行歌词秒数 ≈ 330 ÷ BPM**（→ 需要行数 ≈ 目标秒数 × BPM ÷ 330；说唱/密集短句 ÷1.5）。16 行@88 BPM 实测 54.9/61.0/61.9 秒（±6% 波动）；语义硬上限 9000 帧 = 360 秒。丰富版模板 3.2 节就是这套公式 + 速查表，且其 5 个示例的标注行数与实际行数已用脚本校验一致（教行数预算的模板必须自洽）。
